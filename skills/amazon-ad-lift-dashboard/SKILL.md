# 站内广告加投：测算 → 看板 → 偏差复盘

这个技能把三件事串起来，用同一套口径：

| 模式 | 什么时候用 | 工具 |
|---|---|---|
| **A 测算** | 还没投，想知道“CTR 提到 x% / 每月加 $1,000 SBV / 加 $1,000 SP”能带来多少单、利润怎么变 | `scripts/ad_increment.py plan` |
| **B 看板** | 已经投了，想看排名、每日广告费、各广告类型效果的关系 | `scripts/build_dashboard.py` |
| **C 偏差** | 有一份之前的加投方案，想对比实际跑出来的结果 | `build_dashboard.py --plan`（或 `ad_increment.py actual --plan`） |

用户的问题经常是连在一起的（先看看板，再加分类型对比，再对比方案），三种模式都基于同一份数据和同一套公式，可以逐步叠加，不要每次推倒重来。

公式和口径细节在 `references/formulas.md`，算任何数之前先读一遍。

## A. 加投测算

1. **收集基准（月度）**。需要：展示、点击（或 CTR）、CPC、广告 CVR、销售额、订单数（或客单价）、广告花费、毛利润，以及加广告前的贡献利润率（或“其他成本占比 + 退款率”，贡献利润率 = 1 − 两者之和）。
   - 用户只给了导出文件时，从导出中取最近 30 天，按天数换算到 30 天。
   - 用户给了方案页或截图时，直接用里面的数字，不要另起口径。
2. **写 plan.json**（格式见 `assets/plan_example.json`）。投放动作（lever）有三种：
   - `ctr`：展示不变，CTR 从 `ctr_from`（默认 = 基准点击 ÷ 展示）提升到 `ctr_to`，增量花费按当前 CPC 计算。
   - `budget`：加预算，可以单独给这个类型的 `cpc` / `cvr`（例如 SBV 没有历史数据，借用 SB 的 CPC）。
   - `cpc`：预算不变，只改出价。
   如果之后要做偏差复盘，就加上 `actual_type_map`，写明每个动作对应实际数据里的哪种广告类型。
3. 运行 `python scripts/ad_increment.py plan --config plan.json`。
4. 汇报时包括：
   - 各动作的增量点击、订单、花费、销售额、单均成本、ROAS；
   - 合计数，以及加投前后的销售额、广告费、毛利（率）、TACOS 对比表；
   - 增量利润、每个增量订单的边际利润（对比现有的平均单均利润）、边际利润率；
   - **保本 ROAS = 1 ÷ 贡献利润率**，以及保本单均成本 = 客单价 × 贡献利润率。ROAS 低于保本线的动作，加得越多亏得越多。
   - 要讲清楚这是线性外推得到的理想上限：假设 CPC、CVR 不变，预算能花完，CTR 提升也确实能实现。

## B. 排名 × 广告费看板

1. 用 `--dump-json` 先跑一遍，获取自动分段和各阶段统计：
   ```
   python scripts/build_dashboard.py --data <导出.xlsx> --match 款名=<款名关键字> \
       [--countries 美国,加拿大] --out <输出.html> --dump-json summary.json
   ```
   - 不传 `--countries` 时，默认取销售额最高的两个站点。
   - 同一站点有多个父体时，每个父体有各自的排名。`--countries 美国:B0XXXX` 可以只看某一个父体；整站的排名曲线只代表当天排名最好的那个父体。
   - 如果最后一天的数据不完整（当天销售额不到前 7 天中位数的 20%），脚本会自动剔除；也可以用 `--end` 手动指定截止日。
2. **检查分段**。自动分段是按每天最好的小类排名切的，阶段名比如“排名 #5”。如果用户关心的是特定节点（例如“冲到第 5 名、第 3 名期间”，或“9/22 开始加投”），就写一个 `phases.json` 手动指定，例如：
   ```json
   {"美国":[{"name":"排名6-8","start":"2026-09-01","end":"2026-09-18"},
            {"name":"加投·排名回落","start":"2026-09-22","end":"2026-09-25"},
            {"name":"稳定第5","start":"2026-09-26","end":"2026-10-05","focus":true}]}
   ```
   `focus: true` 的阶段会用暖色底高亮。
3. **读 summary.json，写 notes.json**（格式见 `assets/notes_example.json`），内容包括：标题、顶部 KPI、每个站点的说明和要点、分广告类型的要点、方案偏差的要点、结论与建议。结论要基于数据：
   - 先说清楚排名变化和费用变化的先后顺序。
   - 区分“靠加广告费冲上去的”和“广告费没变、靠自然流量冲上去的”，看广告订单占比和 Sessions 的变化。
   - 指出效率最差的广告类型：ACOS 远高于其他类型，或 ROAS 低于保本线。
4. 加上 `--notes notes.json` 再跑一遍，用 Artifact 发布 HTML；如果用户需要文件，也把文件放进仓库。

看板内容：每个站点一张排名阶梯图（纵轴反转）、每日广告费按 SP/SB/SBV/SD 堆叠、ACOS/TACOS 曲线、每日销量、分阶段日均对比表；分广告类型部分有 ACOS（超过 100% 截断标注）、TACOS 堆叠、7 天滚动 ACOS、花费占比和销售额占比对比、ROAS 和明细表；有方案时再加偏差部分。

## C. 方案 vs 实际偏差

在 B 的命令上加 `--plan plan.json --pre <执行前起:止> --post <执行后起:止>`。

- **先核对基准口径**：方案的基准（例如“30 天销售额 $150K、广告费 $12.5K”）要和导出里执行前的数据对得上，是全站点、单站点还是某个款。对不上时，先换范围（`--countries` / `--match`）找到能对上的口径，并在看板和回复里写明。如果找不到能对上的口径，也要说出来。
- **执行起点**：用实际广告费明显跳升的那一天，或用户告诉你的上线日期；起点之前算执行前，之后算执行后。两段都按天数换算成 30 天月度值，避免天数不同带来的偏差。
- **偏差表**：方案里的每个动作，对照它映射到的实际广告类型；实际有、方案没有的类型，标为“方案外”。
- **利润对比要分两种口径**：
  - 全部增量：订单毛利的变化，包括排名上升带来的自然订单。
  - 广告口径：增量广告销售额 × 贡献利润率 − 增量广告费。这一项才能和方案的“增量利润”直接对比。
  - 两者差距很大时，要明确说出来，例如“总利润涨了，但广告本身几乎没赚钱”。

## 口径与陷阱（来自实际复盘）

- **排名**：同一个父体下的多个变体共用排名，每天取该站点所有 ASIN 中最好的小类排名。排名数值越小越好，图表纵轴要反转。
- **冻结排名**：如果某个父体每天的最好排名在 14 天以上都完全不变（例如 35 天一直是 #9），多半是抓取没有更新。脚本会把它排除在排名统计之外，并在输出里给出警告，请把警告写进看板说明。
- **不完整的最后一天**：最后一天的销售额低于前 7 天中位数的 50%，或广告费低于 30%，脚本会自动剔除。也可以用 `--end` 手动指定。
- **没有方案时怎么判断广告效率**：保本 ACOS ≈ 订单毛利率 + TACOS（订单毛利已扣除广告费）。ACOS 接近保本线，说明广告单基本不赚钱；还要按父体逐个比较 ACOS 和各自的保本线，找出在亏钱投放的父体。
- **结算毛利润受结算周期影响**，短期内会大幅波动，甚至出现负数。短期对比用订单毛利润，结算毛利只列出来作参考，并注明原因。
- **退款、退货、Sessions 有回传延迟**：最近几天显示为 0 不代表变好了，要注明数据还没回传。
- 导出里**没有分类型的点击和展示**，所以 CTR、CPC、CVR 只能看整体。方案里写的是“SP 的 CTR”时，要说明只能用整体 CTR 来近似。
- **计算方式**：比率先求和再相除（Σ广告费 ÷ Σ销售额），不要把每天的比率取平均。
- **图表**：不用双轴图；排名和金额分成上下两张图，共用同一条日期轴。
- **方案页常见的取整误差**：各动作的订单数先取整再相加，会和精确计算差 1 单左右，利润相应差十几美元。复现方案时说明是取整造成的，不要改公式去凑数。
